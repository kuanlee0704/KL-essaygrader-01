# 作文批改室（Google 試算表版）

上傳作文照片，或直接貼上文字，依學測標準批改：分數、評語、可進步之處、滿分改寫、筆記，還能和 AI 繼續討論。

**資料都存在你自己的 Google 帳號裡：**作文與批改結果在「Google 試算表」，照片在「Google 雲端硬碟」，換手機、換電腦輸入通行碼就能接著用。前端放在 GitHub Pages，不需要任何付費服務。

```
瀏覽器（GitHub Pages）  ──POST──▶  Apps Script 網頁應用程式  ──▶  Google 試算表（資料庫）
index.html / js / css               apps-script/Code.gs            Google 雲端硬碟（照片）
                                                                   Gemini API（批改、對話）
```

## 安裝（約 15 分鐘，只做一次）

### 第一步：拿 Gemini API key
到 <https://aistudio.google.com/apikey> 建立一組 key，先複製起來。

### 第二步：建立後端
1. 到 <https://sheets.new> 建一份新的 Google 試算表，取名「作文批改室資料庫」。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把編輯器裡原本的內容全部刪掉，貼上本專案 `apps-script/Code.gs` 的**全部內容**，按存檔。
4. 左邊齒輪 **專案設定 → 指令碼屬性 → 新增指令碼屬性**：
   名稱 `GEMINI_API_KEY`，值貼上第一步的 key，儲存。
   **有多把 key 的話全部貼進同一格，用逗號或換行隔開**，系統會輪流使用，一把額度用完自動換下一把。
5. 回到編輯器，上方函式下拉選單選 **`setup`**，按「執行」。第一次會要求授權：
   選你的帳號 →「進階」→「前往…（不安全）」→ 允許。（這是你自己寫的腳本，這個警告是正常的。）
6. 執行完畢後，下方「執行記錄」會顯示 **你的通行碼**（16 個字元），請抄下來。試算表也多了幾個分頁，通行碼在 `Users` 分頁。
7. （建議）函式選 **`testGemini`** 執行一次。它會逐一測試每個備援模型，紀錄裡 ✅ 代表可用、❌ 代表那個模型名稱不存在或這把 key 沒權限。
8. 右上 **部署 → 新增部署作業 → 類型選「網頁應用程式」**：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

> 之後如果修改了 `Code.gs`，要 **部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**，改動才會生效，網址不會變。
>
> **從舊版升級（已經安裝過）：** 貼上新的 `Code.gs` 後，**再執行一次 `setup`**（只會補上新欄位，不會動到現有資料；就算忘了，新版程式第一次讀寫時也會自動補欄位），再部署新版本。這次新增 `Essays` 分頁的 `ocrInfo` 欄（稿紙格線偵測結果）。前端的檔案（`js/`、`css/`）要一起更新、`git push`。
> 如果你之前在指令碼屬性設過 `GEMINI_MODELS` 或 `GEMINI_VISION_MODELS`，它們會蓋掉新的預設值，想用新的分級備援請刪掉或改掉它們（見下面「模型與備援」）。

### 第三步：把前端放上 GitHub Pages
先在 GitHub 建一個空的 repository（例如 `essay-grader`，**不要**勾選 Add README）。

1. 解壓縮本專案。打開 `js/config.js`，把網址貼進去（也可以留空，第一次開網站時再貼）：
   ```js
   API_BASE: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
   用記事本／文字編輯都可以改。
2. 在專案資料夾打開終端機，依序執行（把網址換成你的 repo）：
   ```bash
   git init
   git add .
   git commit -m "essay grader"
   git branch -M main
   git remote add origin https://github.com/你的帳號/essay-grader.git
   git push -u origin main
   ```
3. GitHub 上該 repo → **Settings → Pages → Build and deployment**：Source 選 **Deploy from a branch**，Branch 選 `main` / `/ (root)` → Save。
4. 等 1～2 分鐘，網站就在 `https://你的帳號.github.io/essay-grader/`。打開後輸入通行碼就能用。

之後更新前端：改完檔案 → `git add . && git commit -m "update" && git push`。

## 作文與題目的輸入方式

「作文」和「題目」都是 **照片區 + 文字區同時顯示**：只用照片、只貼文字、或兩個一起用都可以。

| 情境 | 做法 |
|---|---|
| 手寫作文 | 只上傳照片，AI 辨識字跡（看不清楚的字標 ［？］） |
| 電子檔作文 | 只貼文字：不經過辨識，原文與字數由系統直接填入，比較準，也省額度 |
| 題目是截圖／書面 | 題目傳照片；有電子檔就貼文字 |
| 題目照片＋文字 | 一起提供給老師 |
| 作文照片＋文字 | 畫面會出現「照片和文字的關係」，請選一個：<br>**同一篇**：照片是手寫版、文字是電子版 → 以文字為準，照片只當核對用<br>**接續**：照片是前半、文字是後半 → 合併成一篇整體評分，原文顯示為「照片辨識結果 + 空行 + 你貼的文字」 |

### 手寫作文：建議「先辨識、檢查、再批改」

手寫字（尤其學測的**直式稿紙**）是最容易出錯的地方：原文讀錯，後面的分數和評語就跟著錯。所以流程設計成：

**國文（國寫直式稿紙）→ 用「📐 稿紙格線辨識」**
1. 上傳稿紙照片（正面第一大題、背面第二大題，各拍一張）。
2. 按 **「📐 稿紙格線辨識（建議）」**，會開一個全螢幕視窗：選照片 → 按「智慧抓取四角」（抓不準就手動點四角，可拖曳微調）→ 檢查藍框（偵測有字的格子）→ 按「開始辨識」。
3. 程式在瀏覽器裡把稿紙拉正、切成 38×22 格，只把「有字的欄」拼成長條圖送到後端；後端用辨識模型**逐格只讀一個字**。這樣模型不會跨欄亂讀、不會自己補句子。
4. 辨識完成後，**橘色格＝、與，容易混淆**（雙擊互換）、**紅色格＝和偵測結果不一致或模型看不清**，請人工確認；滑過任何一格會顯示放大圖。
5. 按「寫入作文文字」：看不清楚的字標成 `［？］`；同時記下**稿紙實際用了幾行**，批改時用來核對「超過限定行數酌扣 1 分」。第二張稿紙請選「接在目前文字後面」。
6. 回到作文頁再對照照片檢查一次，確認後按「開始批改」。

> 小提醒：作文照片上傳時解析度提高到長邊 3200 px（題目照片仍是 2400）。格線辨識視窗也可以直接選手機／相機的原始檔，解析度更高、更準。

**國文以外（英文、或不是標準稿紙的照片）→ 用「✨ 整頁快速辨識」**
把整張照片交給辨識模型一次讀完，結果填進「作文文字」，看不清楚的字標成 `［？］`，請對照照片檢查後再批改。此流程用專門的「讀稿紙」提示詞，如果結果出現重複迴圈，會自動換下一個模型重讀。

辨識（兩種都算）和「對話」共用每日次數；一份稿紙不論分幾批送出，只算一次。

**拍照小技巧：** 平放、光線均勻、不要有陰影；整張稿紙盡量填滿畫面、橫向拍；四個角都要拍進去。

字數上限：作文 20,000 字、題目 10,000 字。字數統計：國文算字（含標點、不含空白與換行），英文算單詞；「接續」時兩部分合併計算。

## 日常管理

**新增朋友：** 開試算表的 `Users` 分頁，新增一列：
`name` 填名字、`code` 填通行碼（至少 6 字，建議在 Apps Script 執行 `newCode` 產生隨機的）、`dailyGrades` 每日批改次數、`dailyChats` 每日對話次數、`enabled` 填 `1`。`userId` 留空，第一次登入會自動補。每個人只看得到自己的作文。

**停用某人：** 把該列 `enabled` 改成 `0`（約 1 分鐘內生效）。

**調整額度：** 改 `Users` 的 `dailyGrades` / `dailyChats`；全站每日上限在指令碼屬性 `GLOBAL_DAILY_GRADES`（預設 60）。每次批改會呼叫 Gemini 兩次（先分數評語，再範文筆記）。

**模型與備援：** 三種工作各有一組備援順序，都可以用「指令碼屬性」改（逗號隔開）：

| 工作 | 指令碼屬性 | 預設順序 |
|---|---|---|
| 判讀手寫文字（格線辨識、整頁辨識） | `GEMINI_OCR_MODELS` | `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` |
| 批改、滿分改寫與筆記 | `GEMINI_MODELS` | `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` |
| 對話 | `GEMINI_CHAT_MODELS` | `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` |

預設值寫在 `Code.gs` 最上方的「★ 模型設定區 ★」，直接改那三行即可；指令碼屬性有填的話會優先採用。要升級批改品質，先用 `testGemini` 確認較強的模型能用，再放到 `DEFAULT_MODELS` 最前面。

規則是「每個模型先輪流試完所有金鑰，都不行才換下一個模型」：
- 額度用完（429）或金鑰有問題（401/403）→ 換下一把金鑰
- 模型不存在（404）、伺服器忙碌（5xx）、回傳的 JSON 壞掉或被截斷、辨識結果陷入重複迴圈 → 直接換下一個模型

每篇作文實際用到哪個批改模型，會記錄在試算表 `Essays` 分頁的 `model` 欄。
**第一次部署（或改了模型名稱）請在編輯器執行 `testGemini`**：它會把三組模型逐一測試，✅ 可用、❌ 代表名稱不存在或這把 key 沒權限。
想縮短批改時間可試 `GEMINI_THINKING_BUDGET`（例如 `1024`），模型不支援時系統會自動忽略；辨識固定不開思考。
備援沒有包含 Gemma：批改要讀照片、要求 JSON 輸出，Gemma 不一定支援，需要的話可自行加進清單，先用 `testGemini` 確認能用。

**備份：** 資料就是那份試算表：**檔案 → 建立副本**即可。照片在雲端硬碟的「作文批改室-照片」資料夾。

## 常見問題

| 狀況 | 怎麼辦 |
|---|---|
| 登入時說「後端回傳的內容無法讀取」 | 網址要是 `/exec` 結尾；部署時「誰可以存取」要選「所有人」；改過程式後記得部署「新版本」。 |
| 「通行碼錯誤或已停用」 | 到 `Users` 分頁核對 `code` 與 `enabled`。連續錯太多次會鎖 10 分鐘。 |
| 批改一直轉圈、最後失敗 | 在 Apps Script 看 **執行作業**（左側）的紀錄，會列出每個模型與金鑰失敗的原因；多半是額度用完（等幾分鐘）、key 無效、或照片太多太大。先執行 `testGemini` 檢查。 |
| 「Gemini 免費額度暫時用完」 | 所有金鑰與備援模型都試過了。免費層額度依專案計算，同一個專案下的多把 key 共用額度；想真的增加額度，要用不同專案建立的 key。 |
| 辨識出來的字亂七八糟、一直重複 | 先確認照片：平放、光線均勻、字夠大（字小就左右半邊各拍一張，先傳右半）。系統遇到重複迴圈會自動換模型；全部失敗時改用「貼上文字」。辨識後務必對照照片修改再批改。 |
| 部署後行為沒變 | 沒有部署「新版本」。 |

## 運作細節與限制（請先讀過）

- **批改在背景執行：** 按下「開始批改」後，網頁立刻要後端開始做，並每 4 秒查一次進度；分數評語先出現，範文與筆記晚約半分鐘補上。關掉網頁也不會中斷，下次打開同一篇會自動接著等。萬一網頁那一步失敗，後端的保險觸發器會在約 1 分鐘後接手。
- **分數由程式重算與把關：** AI 給各項分數（一律整數），總分由後端用「各項加總 − 扣分」計算；國寫各小題的**等級依大考中心的分數對照表重算**（25／21／18／7／4 分題各有自己的級距）；「至多 B+」這類特殊評分原則（例如沒表明立場、沒訂題目、缺角色對白情節）由模型標出、程式把分數壓到上限；英文作文配分固定 5/5/4/4/2，內容 0 分（文不對題）時其他項一律 0 分。
- **通行碼是唯一的鎖：** 後端網址不是機密，任何人都能呼叫，但沒有通行碼什麼都做不了。請用隨機的長通行碼，不要用生日之類猜得到的字。
- **規模：** 試算表當資料庫，適合幾個到幾十個人、每人幾百篇以內；再大請改用真正的資料庫。
- **隱私：** 作文照片會送到 Google 的 Gemini API。Google 的條款通常允許免費層的內容用來改進產品（請以最新條款為準）；如果在意，請在 Google AI Studio 為專案啟用計費（付費層通常不會拿去訓練），或事先告知使用者。
- **Apps Script 的每日配額：** 免費帳號有每日執行時間等上限，用量大時可能暫時被限制。
- **評分標準來源：** 國文依《學科能力測驗國文考科考試說明（111 學年度起適用）》，英文依選才電子報第 180 期〈英文考科非選擇題評分標準說明〉（98 指考）。級距表在 `Code.gs` 的 `ZH_BANDS`、`enLevel_` 與 `ZH_CORE`／`EN_CORE` 提示詞裡。每年實際閱卷時，各題會另訂該題的評分原則，AI 只能依通則評分；英文標準若與最新學測英文考科說明不同，請自行更新提示詞。

## 檔案結構

```
index.html            頁面骨架
css/style.css         樣式
js/config.js          後端網址（只改這個）
js/api.js             和後端溝通
js/ocr.js             稿紙格線辨識視窗（切格、偵測、逐格辨識、人工校正；樣式在 style.css「稿紙格線辨識視窗」區）
js/store.js           資料層：快取、合併儲存、照片快取
js/app.js             畫面與互動
js/theme.js           外觀設定
apps-script/Code.gs   後端（貼到 Apps Script）
apps-script/appsscript.json  選用：專案設定檔（時區、權限範圍）
```
